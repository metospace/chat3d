# Scenivo

通过对话生成和修改可编辑的工业三维场景，支持静态沙盘与通用关键帧/表达式动画。前端为 React、TypeScript、Three.js；Web 使用同源模型代理，另有 Tauri 桌面端源码。

0.2.1 把用户看到的产品名从 Chat3D 改为 Scenivo。仓库仍是 `WangZai6936/chat3d`，桌面更新地址仍是 `https://portal.jiezi-ai.com/desktop-updates/chat3d/latest.json`。

0.2.0 新增单团队账号、团队资产库和场景库。个人草稿留在本机，显式确认后才发布；团队版本不可变，复制不覆盖原件。部署需要 Node.js 24 与持久化 SQLite 目录。详见 [团队部署、账号与使用说明](docs/TEAM-SHARING.md)。

## Agent 依赖

连续建模使用 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai`，均固定为 `1.5.0`。项目直接使用 `Agent` 和 OpenAI-compatible 流式适配器；会话、草稿、建模工具与复核规则由 Scenivo 管理，不依赖 1.0 已移出的实验性 AgentHarness。

此升级不自动接入 Pi Coding Agent 的 Codemode、MCP 登录或终端界面，也不代表整体任务 Token 减少 40%。这些是独立能力，需要按产品需求另行集成。

1.5 使用增量工具参数解析，并统一通过 pi-schema 校验 JSON Schema。现有工具定义保留 TypeBox，显式依赖 `typebox@1.3.27`，不再从 Pi 重导出接口导入。工具封装使用 TypeBox `Static` 保留元组和联合参数的完整静态类型；运行时仍由 Pi 校验后执行。结构生成回归覆盖向量长度、数字字符串转换、无效几何及重复数量边界。该升级不改变 Scenivo 的任务预算、缺陷阻断和人工应用流程。

## Blender 建模（实验）

在首页或工作台输入框底部的生成菜单选择「Blender 生成」可通过 MCP 调用本机 Blender；默认「直接生成」使用普通建模链路。菜单保留快速/精细档位，不再提供写实/简洁风格或独立 Blender 复选框。首页提交时将选择带入工作台。Blender 导出的 GLB 自动进入主画布预览，应用后可按零件编辑和保存，撤销可恢复原场景。不额外运行 Scenivo 建模或质量复核。原始 `.blend`、GLB 和渲染 PNG 可在对话中展开下载，只保留在当前会话。使用条件及任意 Python 风险见 [Blender 本地适配器](server/blender/README.md)。

Blender 代理已内置从 `blender-mcp-modeling 1.0.1` 提炼的通用建模质量规则，按当前需求加入 SMT、操作件、键鼠终端或机构动画专题；执行中补充需求也会加入对应规则。不加载原机器路径、安装配置、固定品牌和产线数值，不调用第三方 MCP 或质检脚本。规则指导 Blender 内建模，不修改返回文件，不代表生成质量已验收。

## 本地启动

使用 Node.js 24.x，与 Docker 镜像和 CI 一致。`.nvmrc` 提供版本选择，`npm ci` 会提前拒绝不受支持的 Node 版本；切换到 Node 24 后再安装依赖。

```sh
npm ci
npm run dev
```

生产 Web 部署：

```sh
npm run build
npm start
```

不能仅把前端静态目录上传到不支持代理的服务器。自定义模型地址、生产域名及 Docker 部署见 [PROXY.md](PROXY.md)。不要将 API Key 放入仓库或前端构建变量。

## 使用流程

1. 配置真实模型地址、Key 和模型 ID（不提供离线模拟生成）；连续建模需要服务支持工具调用、图片和流式输出
2. 描述场景或上传参考图；已有选中对象用于指代，默认不限制整个场景的修改范围
3. 每轮对话内查看计划、工具执行、错误和结果；耗时与用量放在次要位置
4. 连续建模执行中可发送文字或图片补充要求；当前工具完成后跳过未执行的旧操作，将新要求送入下一轮模型上下文。消息标明等待、已接收或未送达；停止后未送达内容可恢复。单次生成兼容模式暂不支持运行中引导
5. 生成结果先展示为草稿。可以直接继续发送调整要求，无需先应用；连续草稿最终应用为一笔可撤销事务
6. 满意后应用，或放弃整条未应用草稿。属性面板可直接“应用当前草稿并编辑属性”；应用和后续手动修改分别可撤销。中断时保留成功阶段；后续失败不会丢掉此前预览
7. 未应用的预览与执行中的任务均属于各自会话。可切换或新建会话并继续建模；当前标签页最多同时执行 2 个会话，同一会话顺序执行。第 3 个请求会明确拒绝并保留输入，不自动排队调用模型
8. 动画可在视口播放、暂停、拖动时间和调整速度；详见 [ANIMATION.md](ANIMATION.md)
9. 结构树眼睛只切换对应部件，隐藏行显示「已隐藏」。重叠的玻璃、屏幕底板或支架独立可见；隐藏其中一件不会连带隐藏其他部件。可再次点击显示，或撤销该操作。

## 导出文件

- 画布顶部“导出”中的 HTML、GLB、项目 JSON：桌面端先打开原生保存对话框，可选择文件夹和文件名；取消不写文件、不显示成功提示。确认覆盖已有文件后会替换该文件，写入并同步成功后才提示保存路径。
- Web 端继续由浏览器下载，提示“已发起下载，请检查浏览器下载”，不把下载触发当作落盘确认。导出成功或失败均使用约 4 秒自动消失、可手动关闭的提示，不占用内容区常驻通知条。
- HTML 是可离线查看的静态模型；GLB 包含静态模型和材质。需要动画与可编辑工程时请选择项目 JSON。导出不改变资产/场景的入库状态；工作台与诊断备份仍使用原有保存方式。
- 手动验证：桌面端分别导出三种格式，选择非默认目录并打开文件；再取消一次，确认没有文件或提示；浏览器分别下载，确认提示自动消失且没有灰色常驻横条。

## 删除场景模型

- 在画布或“结构”中选中对象，点击工具栏垃圾桶“删除选中对象”，或按 Delete。Shift / Ctrl / ⌘ 点击可多选；“结构”中的组件名称或视口“选择整台设备”可选中整组。
- 删除模型会移除选中零件及其子节点，并清理相关连接、动画目标和已删除的跟随源。一次多选删除是一笔历史，可用撤销/重做完整恢复；不再限制一次只能删除 10,000 个目标，仍校验全部目标与引用并整批提交或回滚。
- 对话可真正删除场景对象，仍先预览、后应用。明确的“删除选中的对象”或唯一模型名称走本地命令；歧义或复合要求交给模型判断。输入文字、生成中和待确认预览时不会触发键盘删除。
- 只改变当前会话场景，保留独立资产库的原件、版本、文件和材质。其他会话的模型与历史不受影响。

## 框选与多选属性

- 工具栏“框选对象”默认关闭“穿透”，按选框内最近几何表面的 ID/depth 像素选择；仅投影包围盒相交不再足以选中。开启“穿透：开”才包含前方对象后面的几何，穿透也按实际三角面相交判断。
- 拖动方向不影响结果，部分相交即可命中；Shift / Ctrl / ⌘ 追加，Esc、指针取消或切换模式会取消当前拖动。切换会话会关闭框选和穿透。
- “框选零件”不扩展选择。“框选模型”在命中零件后包含该模型全部成员，包括隐藏和框外成员。货架真实孔洞中露出的后方零件仍是可见几何，可能命中；如只需前方零件，可缩小选框或从结构列表选择。
- 可见选择按当前绘图缓冲区分辨率进行无抗锯齿 ID 渲染，每次读回最多 1024 × 1024 像素。小于一个像素的细杆/边缘可能没有命中像素；透明面按实体选取，不模拟透明叠加和贴图 alpha。装饰地面、网格、选框轮廓不作为模型选择目标。它不是与显示图像抗锯齿完全一致的像素分割。
- 三维上下文丢失或读回报错时保留原选区并显示错误，不悄悄改成穿透。测试覆盖数学相交、模拟 ID/depth 读回及状态恢复；实际 WebGL 驱动仍需在可用浏览器检查：本地运行 `npm run dev` 后打开 `/e2e/rectangle-selection.html`，点击运行按钮。
- 画布属性面板对选中零件的移动、旋转、等比缩放和改色使用一笔手动属性事务，不再受 200 个独立零件限制，不扩大到未选中的同模型零件。数值/文档校验失败则整笔不应用；成功后一笔撤销/重做。此同步事务没有中途取消按钮，应用前可关闭面板，应用后可撤销。“更多属性与材质”的批量颜色、表面参数和已有材质替换也采用同样事务，保留原材质筛选。AI 的每批命令、新增节点及资源预算保持不变。
- 资产详情操作统一为“编辑资产 / 编辑信息 / 更新预览图 / 版本与备份”；移除“用于新场景”。场景画布资产架仍可引用固定版本资产。

## 检查原则

- 用户的明确业务要求优先于默认方案、旧助手假设和高亮选择
- 名称、分类等非视觉修改不要求截图；单组件外观可近景检查；结构和布局使用全景；动画使用动态样本
- 元数据变化不会使已完成的视觉检查失效；批量复制允许完成后统一检查
- 保留结构合法性、修改范围、网络安全及实际资源预算；批次容量不足应分批处理，不能擅自削减目标
- 自检是生成辅助，不是工程认证、物理仿真或人工验收

## 大场景与重复资产

- 场景编辑和项目 JSON 重开没有固定的总对象数门槛；GLB 导入不再按总部件数截断。保留每个部件及固定资产版本；提示明确要求完成全部数量与位置，不能把每批容量误当成只需完成前 16 个或顶层。
- `add_saved_assets` 每次最多 16 个实例，继续分批才能完成更多位置；同一批次的同版本资产只读取一次。每次成功后仍使用现有阶段草稿保存机制，失败整批不改。恢复时须根据当前实例和位置继续，尚未实现自动分配位置、后台队列或刷新后自动续跑。
- 本地项目 JSON 文件上限为 100 MiB，手动放置和阵列复制使用同一预算。单个资产输入与 GLB 文件预算为 50 MiB，团队发布采用 50 MiB 格式校验上限及 55 MiB HTTP 请求体上限。每批 200 条命令 / 3,000 个新增节点、单组件构建限制、网格和贴图预算，以及任务时间/轮数/Token 预算均保持不变。触及实际资源保护会明确失败或保留未完成草稿，不会静默删减用户数量。
- 项目 JSON 改用紧凑序列化。追加模型不反复复制已有节点，文档父引用校验改为线性遍历；视口对同几何、同外观复用资源，各节点仍可独立编辑。视口对至少 16 个相同几何、材质和绘制设置的静态不透明零件采用 GPU 实例化，保留独立节点用于选择与编辑。透明、动画目标和镜像变换保留逐节点绘制；浏览器内存、显卡和截图预算仍影响可用规模。
- 容量回归使用确定性 28 零件资产 × 400 实例（11,200 节点）和 10,017 部件 GLB，覆盖分批生成、完整数量核对、预览应用、撤销/重做、替换、保存重开、资源复用及失败回滚。不代表任意硬件的帧率或真实模型服务生成质量已经验收。

## 需求核对与恢复

- 连续建模工具 `check_requirements` 整理用户原文中的明确要求，优先按同名完整组件核对数量和世界坐标包围盒尺寸，没有匹配组件时可匹配组件内零件（如台面、金属腿）；米制尺寸容差为 2% 或 1 厘米取较大值
- 自然“长×宽×总高”按 X×Z×Y 核对：length/width/height 分别对应几何 width/depth/height；“宽×深×高”按 X×Z×Y。明确其他轴、旋转或混合约定时保守标为待核对，不能拿另一维度的数字充当符合
- 三维不可用时，当前响应中的有效数据编辑结束后直接返回未经视觉验收的阶段草稿；截图运行失败最多尝试一次，不再自动循环复核。可继续修改或手动保留，恢复三维后再验收。纯文本结束回复不再自动续问，已有修改保持未确认
- 配色部位、排布语义、造型真实度和工艺仍标为待核对；找不到组件名称不等于缺失。模型提取可能遗漏，清单不代表全部需求已覆盖
- 不符合或未核对项随预览显示，允许保留阶段草稿，不以新检查无限阻止提交
- 执行中发送的消息先保存在输入框上方队列，可显式选择引导或只提问。只提问不允许模型修改场景；未发送的后续任务须手动准备并发送，不会自动调用模型
- 失败时可在对话展开「失败原因」并恢复输入。任务记录 → 问题排查可下载完整诊断，包含可取得的模型请求和回复、服务返回的推理内容、工具参数和结果、Blender 脚本、参考资料、场景、操作历史及实际错误；连接凭据和执行令牌除外。历史任务中未记录的内容无法补回，分享前请检查敏感资料。

## 数据与交付边界

- 并行任务运行在当前浏览器标签页，切换项目不取消任务；关闭或刷新页面会中断，重新打开只恢复已保存阶段草稿并标明中断，不自动续费调用。停止仅取消当前会话的接收，服务方可能仍在处理并计费用量。
- 并行截图使用单独的离屏三维场景并串行占用检查渲染器，不借用正在查看的会话画面；不可用时退回服务端或软件几何检查，软件图不能验收材质、光影或动画。
- 会话、执行历史及草稿在当前浏览器的 IndexedDB 自动保存；顶部显示保存进度或异常，并非云同步或多人协作。保存时在同一事务回收不再被清单引用的旧字段，保留回收站内仍可恢复的会话、当前草稿和历史；失败或旧标签页冲突不会部分回收数据。
- 在资产库或场景库的「草稿」中，可以从详情单项移至回收站，也可以用「批量整理」一次移入多项。正在执行的草稿不能移入；可从会话回收站恢复草稿、聊天和参考图。已入库资产和版本不会被移入回收站。
- 底部“尚未导出备份”只指项目 JSON 下载状态，与会话自动保存分开；下载发起后仍需自行确认文件落盘
- 模型地址、模型选择及预算保存在 localStorage；Key 默认仅留在本次会话内，刷新后需重新输入。只有明确勾选“在此设备记住密钥”才明文持久化。旧版未明确选择记住的 Key 会在载入时迁移为本次会话使用并从持久存储移除；当前不是企业凭据管理方案
- 项目 JSON 保留可编辑场景和动画；GLB 和 HTML 当前仅导出静态可见模型。工作台「导出 → 导出模型 HTML」将模型、材质与查看器打包为单个文件，保存后双击即可用支持 WebGL 2 的新版浏览器离线打开，无需本地服务或 CDN；支持旋转、平移、缩放和重置。HTML 不包含聊天、模型密钥或隐藏对象，不是可编辑工程，长期编辑请保留项目 JSON。
- 下载项目文件用于长期备份。聊天和任务历史保存在本地会话中，不包含在项目 JSON 中
- 当前动画基于对象变换、显隐、跟随及受限表达式；不支持任意脚本、骨骼蒙皮、物理或生产工艺仿真
- 桌面端源码存在，不代表已完成各系统安装包发布与兼容性验收

## 0.2 工作台优化

- 界面统一采用中性主题：管理页为轻量侧栏、创建输入与真实项目卡片；工作台为结构/属性区、独立三维画布与 AI 对话区。全局「任务」位于顶栏右侧，点击打开支持搜索和状态筛选的队列抽屉；当前项目执行记录仍在 AI 面板内。版本入口位于管理页侧栏底部，工作台通过左上应用图标进入；沿用安全更新与备份流程。小于 1200 像素时编辑面板与助手切换显示并保留输入，小于 540 像素时画布与助手上下分区。
- 明确且唯一目标的单项改色、带引号改名、米/厘米/毫米移动和 box 单零件宽高深编辑优先使用本地命令。不是离线模拟生成：不创建替代场景，不猜测歧义，仍经过范围、位置锁、动画保留与预览确认。含图片或复合指令进入真实模型。
- 新增有界 `profile` 凸轮廓挤出与 `lathe` 旋转剖面，供模型表达斜切壳体、肩腰轮廓、变径构件。与视口、尺寸包围盒和 GLB 导出共享实现；旧版应用可能无法打开包含新类型的项目。
- 模型可读取可编辑结构参考：连贯弯臂的操作人员、空腔设备、梁柱货架、带防撞与导航结构的AGV。它们不是自动替换用户任务的演示，也不等于特定厂家的真实产品。
- 业务路线工具以相对位移、速度、停留、返回路径和载物绑定编译为原有动画轨道，保留不相关轨道；不做物理碰撞或自动避障，延长总时长会影响整个循环周期。
- 项目菜单增加“工作台检查与备份”：运行状态、场景质量线索、全部会话项目与聊天文字迁移。未确认草稿单独导入副本，不覆盖原项目。备份不含参考图片、撤销栈、模型API配置与密钥，用户自己写入聊天的敏感内容仍在聊天文字中。
- 工作台备份导出与导入统一采用 200 MiB UTF-8 总预算及单项目 100 MiB 预算，不再因超过 100 个会话、10,000 条消息或 200,000 字符而拒绝恢复或截断输入。全部会话与草稿校验通过后才追加导入；长聊天和输入文字原样保留。
- 浏览器版会检查 `/api/version`。发现新版本时可以稍后更新，或在结束生成并下载备份后刷新页面。桌面版只在发布构建配置了 https 更新源和签名公钥后下载已签名安装包；生成进行中不会强制重启。门户清单是 `https://portal.jiezi-ai.com/desktop-updates/chat3d/latest.json`。0.2.7 起，清单可以列出同一安装包的 `mirrors`，客户端下载前选用较快的地址，签名校验不变。发版与配置见 [应用更新](docs/APP-UPDATES.md)。回滚前保留新格式项目副本。

### 验收分层

1. 自动化：`npm test`、`npm run build`、`node tests/worker-proxy.mjs`。
2. 用户操作：创建→预览续改→确认→撤销→保存→重新打开，检查对象、尺寸、材质、动画和会话隔离。
3. 真实视觉：必须在可运行WebGL的浏览器检查全景与近景、人物比例、设备空腔及部件连接、物流路线与动画；CPU数据检查和离线渲染不能冒充浏览器三维验收。
4. 模型用量：分别记录本地明确编辑和真实模型生成，不能把0Token短路径推广为复杂建模成本承诺。

## 独立资产库与场景库

- “资产库”是独立管理页：新建后进入空白资产编辑项目，生成/导入并应用预览后保存到库；无需先创建场景或选中零件。首页和资源库只展示真实本地内容。
- 已保存资产可打开为独立编辑项目；保存创建新版本，旧版本保留。并发版本冲突会拒绝覆盖。资产目前保存静态模型，含动画项目需保留为场景或导出项目。
- 完整资产备份总预算为 200 MiB。
- “场景库”独立列出场景项目，支持新增、打开和“保存场景”。已有普通会话保留并作为场景草稿展示，不删除旧数据。
- 场景中“引用资产”使用资产的固定版本。实例可以调整与撤销，不修改资产原件；资产升级不会静默替换场景中旧实例。
- 编辑草稿自动保存在当前浏览器，明确点击保存后标记入库；目前没有账号云同步。工作区备份保留资产/场景类型，导入的资产编辑项目不继承对原资产的版本写入关系。
- 资产分类与场景分类独立，支持一级分类和子分类。目录可以搜索、折叠，分类管理使用目录浏览与信息编辑两栏；重命名不改变稳定标识、历史版本或场景引用。资源列表支持跨分类搜索、排序、网格/列表、多选和批量移动分类；运行中或待确认项目不允许部分整理。
- 已保存资源可从详情或多选操作直接发布到团队。发布前冻结并确认，批量显示逐项结果；团队登录在本次应用会话跨页面保留，退出或刷新后清除。手动检查团队版本后可“获取新版并保留旧副本”，已编辑的本地内容、历史版本和预览不会被覆盖；这不是自动同步。详见 [团队共享](docs/TEAM-SHARING.md)。

## 执行可见性与紧凑收尾

- 聊天工作时间轴只展示公开工作说明，同一阶段的连续说明合并为设计、构建、复核或修正记录；不展示工具调用、模型轮次或原始错误。时间来自实际说明事件，旧记录缺失则明确标注，不补造；“已结束”不代表质量通过。输入框无“参考”设置按钮，附件上传、粘贴、拖放和自动沿用参考图保留。
- 参考图连续建模默认提供 `build_modeling_program`：模型编写参数化 Three.js 函数，直接表达曲线挤出、分层截面、管线与独立 PBR 部件；不必把所有形状塞进基本体 JSON。先主剪影取景校正，再细化。源码随项目保存，可读取修改；已有局部编辑、位置锁和人工确认规则不变。这是构建能力升级，不是相似度或质量保证。
- 工具组可一次批量启用和收回；源码默认只读参数头/声明目录，按查询或范围读取片段，`patch_modeling_program` 用版本号和精确局部替换在内部重建，不重复发送完整程序。过期源码和同版本已被更新的重复视角按需精简，原参考图与尚未替代视角保留。截图回执提供真实组件引用和复核范围，减少重复查询与复核协议往返，不放宽验收。
- 运行中直接用“发送引导”“发送问题”“保存后续任务”按钮提交。引导等当前操作结束后接收；问题禁止编辑；后续任务仅记录，需用户主动发送。
- 相同版本、相同目标与参数的截图复用，不重复渲染来制造进展。场景改变后重新取图。
- review_model 支持 completion，把已读取真实图像后的复核与预览提交合并；仍执行原提交校验，不能绕过最新证据、动画检查或未验收项。
- 场景修正按差异推进：先全景定位，再修改当前1–2个目标并近景复查，不先遍历所有组件填表。模型每轮最多携带6张生成检查图，其他原图在本次运行归档、可分页取回，原参考图始终保留；归档不代表验收，过期与未实际送达的图不能通过检查。共享场景约束只读当前布局、比例和材质，局部修改不重建无关组件。
- 单体流程建议合并可顺序执行的工具调用。实际轮数、耗时与Token取决于模型和任务，未承诺固定轮数或同质量加速比例。
- 建模命令使用统一契约，任一操作无效则整批不执行；可确定的字段错误在原任务预算内由模型纠正，最多两次额外纠正轮。无法恢复时保留有效草稿；对话显示可操作的失败摘要，并可展开实际错误。完整诊断可在任务记录中下载。

### 单体复核范围修正

托盘真实验证发现：唯一可见模型的完整组件图曾被当作局部图，导致提交时再要求全景。现在仅当取景目标覆盖原始场景的全部可见几何节点时，才同时作为全景证据；多对象或隔离诊断仍不能代替全景。空场景不再提供无目标的 detail_quality_standard 查询，固定标准仍在系统说明中，生成模型后恢复此工具。

验证样例为文字生成九脚网格托盘，不是用户原截图的同提示词对照：v85 实测 12 轮 / 12 工具 / 271660 已报告 Token，生成 57 零件并提交待确认，约 3 分多钟。发现上述两轮额外取图后修正，用真实守卫和模拟模型回放验证单对象可提交、多对象仍拒绝。没有把修正后的理论少两轮当作新的真实计时结果，也未声称全部材质质量通过。

## 运行与维护优化

- 新配置的默认预算为 10 分钟、24 轮、200 万已报告 Token；设置中可选小改动、常规建模、复杂场景或自行填写。已有明确保存的预算保持不变，达到上限保留阶段草稿，仍需手动继续。
- 离线 HTML 导出运行库按需加载，首次点击导出时下载；生成的 HTML 仍是自包含离线文件。
- AI 上下文裁剪、工具参数 Schema、提示词分别位于 `src/ai/agentContext.ts`、`agentSchemas.ts`、`agentPrompt.ts`，执行状态与工具守卫保留在 `modelingAgent.ts`。
- `npm run build && npm run test:runtime` 按 Docker 运行阶段 COPY 清单组装临时目录，验证服务启动和版本接口；实际容器环境仍可单独验收。
- `node tests/instancing-browser.mjs` 检查真实 WebGL 像素一致性和绘制次数，可通过 `CHAT3D_BROWSER_PATH` 指定本机 Chrome/Edge。该测试不代表大型场景的硬件帧率。
