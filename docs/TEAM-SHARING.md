# 公司内部团队共享（0.2.0）

沿用 React/Vite/Tauri 与 Node 服务。首版是**一个公司、一个团队**：所有有效成员可查看、搜索、预览并复制已发布资产和场景；个人 IndexedDB、草稿、对话、模型 API 设置仍保留本地，没有后台同步或迁移上传。团队账户与模型 API 账户无关。

## 部署

需要 Node.js 24、一个持久化本地磁盘目录，以及由公司指定的 HTTPS 反向代理。SQLite 是 Node 内置模块，无新增数据库服务；静态看板使用 npm 锁定的 `yauzl` / `yazl` 处理流式 ZIP，Docker 运行层已包含所需依赖。不支持将数据库及看板内容目录放在临时容器层、网络共享磁盘或多个副本中运行。Sites/静态托管/现有 Worker 不提供团队数据库；桌面安装包也不内嵌数据库服务器。

在选定服务器检出提交后：

```sh
npm ci
npm run build
export CHAT3D_TEAM_DB=/srv/chat3d-data/team.sqlite
# 浏览器实际来源必须精确匹配；不要设置通配符。
export CHAT3D_TEAM_ORIGINS=https://team.company.example,https://portal.jiezi-ai.com,http://tauri.localhost,tauri://localhost
# 协同平台（路径 A）。默认指向公司协同认证；只转发用户 accessToken，不使用服务账号令牌。
export CHAT3D_PLATFORM_AUTH_BASE=http://36.133.218.210:48080
export CHAT3D_PLATFORM_TENANT_ID=1
# 设为 0 时关闭本地团队密码登录（返回 403），只保留协同账号换票。
export CHAT3D_TEAM_PASSWORD_LOGIN=1
export HOST=127.0.0.1
export PORT=1420
npm start
```

Dockerfile 同时包含团队校验器。容器部署时将受限持久卷挂载至 `/data`，显式设置 `CHAT3D_TEAM_DB=/data/team.sqlite` 和来源白名单；目录须可由容器的 node 用户写入。不要将生产数据库放入构建上下文。

首次运行前由服务器管理员创建持久目录并限制服务用户访问。反向代理将指定 HTTPS 域名转发到 127.0.0.1:1420，旧单请求接口上限采用 512 MiB（`client_max_body_size 512m`）；新 gzip 分块接口每请求仅需 2 MiB。请求体接收、上游发送及响应读取超时均设置为至少 900 秒。公司域名、证书、服务器位置和运行账号须由部署方提供；仓库不含生产凭据。不要向公网开放无 TLS 的 Node 端口。已有模型代理配置保持独立。

网页本机测试可以使用 `http://127.0.0.1:1420`，将实际浏览器来源加入 `CHAT3D_TEAM_ORIGINS`。Vite 不内嵌团队数据库：另起 Node 团队服务（例如 `PORT=1422`），在 Vite 环境设置 `CHAT3D_TEAM_DEV_BASE=http://127.0.0.1:1422`，重启 `npm run dev` 后由 `/api/team` 代理到该服务；代理不移除浏览器 Origin，白名单仍需精确配置。也可用 `VITE_CHAT3D_TEAM_DEFAULT_BASE` 显式选择远程服务，并配置其 CORS 来源。桌面客户端保留既有 Tauri 权限，仅支持标准 HTTPS 443（本机测试 HTTP 80），不要扩大客户端通配权限。未设置 `CHAT3D_TEAM_DB` 时共享 API 不启用。

### Web 工作空间（与客户端共用业务）

`/team/` 不再是只读下载门户。它与客户端使用同一个 `App`、生成链路、本地资源库、团队页面及发布/获取逻辑。`npm run build` 同时输出桌面主应用 `dist/`、团队校验器 `dist-team/` 和子路径 Web 构建 `dist-team-web/`；Node 服务提供 `/team/` 与独立的 `/team/sso/callback` 授权结果页。

- 两端都支持需求/参考图生成、继续修改、预览确认、保存资产与场景、批量发布、检查更新及获取固定版本。Web 获取后直接进入当前浏览器的本地库，不再要求下载导入客户端。
- 浏览器和客户端的本地工作区独立；团队同步指显式发布与获取版本，不自动上传草稿、聊天、参考附件或模型密钥，不是实时协作。关闭页面会中断页面内生成，不提供服务器后台生成。
- 文件保存和网络使用各自平台适配；Web Blender 仍需单独启用适配服务，不会把浏览器当作本机 Blender。
- 浏览器根入口和 `/team/` 默认使用当前 HTTP(S) origin；桌面默认使用 `https://portal.jiezi-ai.com`。`VITE_CHAT3D_TEAM_DEFAULT_BASE` 在两端优先。授权回调默认位于所选服务的 `/team/sso/callback`，可由 `VITE_CHAT3D_PLATFORM_OAUTH_REDIRECT_URI` 显式覆盖；必须在协同平台登记完全一致的 URI，secret 仅配置于服务端。
- 回调页先移除 URL 凭据，单次兑换授权码并保留 `state` 通知同源等待窗口；等待方忽略缺失、过期或不匹配的授权结果。同源 Web 用 BroadcastChannel/storage，跨源 Web 与 Tauri 用一次性 state claim 完成登录，不重复兑换 code。成功页提示返回原工作空间；失败页和原同源窗口显示具体错误。
- 更新部署需要同时发布 `dist-team-web/` 与服务代码；客户端共享业务变更需要重新构建安装包。旧只读 Web 页面和样式已移除。
- 单次兑换回归：`node tests/team-oauth-callback.mjs`（本地 HTTP 服务，覆盖回调兑换、令牌优先级、BroadcastChannel/storage/focus，以及跨源桌面 `claim` 轮询）。
- 平台授权码兑换支持 `{code:0,data:{access_token,refresh_token,expires_in}}`，优先读取内层 snake_case 令牌，兼容内层 camelCase 与顶层 OAuth 令牌字段；有效期优先使用 `expiresTime` / `expires_time` 绝对时间，否则将内层或顶层 `expires_in` 秒数换算为毫秒时间戳，缺失时为 `0`。`node tests/team-library.mjs` 使用本地平台 HTTP mock 验证兑换、团队会话、有效期优先级及未配置 secret 的 503。

浏览器验收已使用生产 `/team/` 构建与临时 SQLite 团队服务，验证保存场景、发布 v1、独立浏览器存储的根入口获取 v1 并向同一原件追加 v2、原入口发现新版、旧基线发布拒绝、获取 v2 后旧场景保留。生成预览与应用使用隔离模型响应验证，不代表真实模型质量；登录使用模拟协同身份，不代表生产 SSO 配置已验收。客户端原生网络/发布由现有契约回归覆盖，未在此次验收中启动安装版客户端。

构建及授权、团队版本关联、权限、分类、发布幂等和静态路由回归已通过。构建仍提示主应用大块约 5 MB（gzip 约 1.31 MB）以及部分动态导入不能独立分块；本次未把这些警告当作加载性能已优化的证明。线上域名与生产账号登录仍需部署后验收。

## 账号管理

没有开放注册或默认密码。管理员通过服务器命令创建账户，密码从标准输入读取（不少于12字符，最多256字符），不要放在命令行参数、仓库或日志中。以下交互提示中的密码由管理员自行选择：

```sh
read -rs -p 'New account password: ' TEAM_PASSWORD; printf '\n'
printf '%s' "$TEAM_PASSWORD" | node server/team/admin.mjs add alice member
unset TEAM_PASSWORD
# add 名称 admin|member|viewer；禁用账号立即撤销全部会话：
node server/team/admin.mjs disable alice
```

角色：`viewer` 只能读取和获取；`member` 可发布新原件和追加自己的原件版本；`admin` 可追加任意原件版本。现有版本不可编辑或删除。账号管理仍使用服务器命令，不向客户端提供提升权限入口。数据库保存 scrypt 密码哈希和会话 token 哈希，会话8小时过期。团队会话 token 保存在桌面进程内共享单例：切换资产库/场景库/团队资源等模块或离开团队页再返回仍保留连接，无需重新授权。关闭应用后需重新换票；默认会把协同 access/refresh 写入本机 localStorage（与模型 API Key 同级），下次打开用已保存的 accessToken 静默兑换团队会话；不保存协同密码。仅服务根地址与可选协同令牌保存在 localStorage；客户端不跟随 API 重定向。Windows/Tauri 沿用原生 HTTP 插件的既有权限范围与正常 TLS 校验。

## 看板库

### 管理与使用

- 使用相同团队服务、SQLite 持久目录和账号角色，不需要另一个数据库。主导航「看板库」内，只有 `admin` 显示上传、发布新版及上下架管理操作；服务端独立校验权限。现有协同首次登录默认 `member`，管理员账户须按上述账号管理流程预先配置，不提供客户端提权。
- 上传弹窗提供「选择文件」「选择文件夹」和拖放区域，显示源码名称、相对路径清单、文件数量、总大小及移除操作。自动识别各层级 `.html` / `.htm` 入口；文件夹上传移除最外层所选目录名，保留其内部目录结构，入口例如 `index.html` 或 `dist/index.html`。ZIP 保留原包，入口按包内路径选择。所属系统可直接输入自定义名称（最多 80 字符），已发布名称自动进入列表筛选与下次上传的建议选项。
- 不再设置看板原包总大小、解压总量或文件数的业务上限。浏览器按文件切片，每次最多发送 1 MiB 实际数据，服务端确认落盘后累计进度。取消保留选择，失败重试沿用同一幂等键并从已确认偏移继续。实际容量受浏览器、网络、磁盘与代理限制。看板及模型分块上传每请求仍限 2 MiB JSON，模型发布完整内容及压缩包限 500 MiB；最终校验/落库代理响应超时需允许 900 秒。
- 接受包含说明、配置和附属脚本的完整源码目录及无加密 ZIP / ZIP64，不因 README、LICENSE、`.vue`、`.ts`、`.py`、`.cjs` 等附属文件拒绝整包；这些文件原样保留，不在服务器执行。服务端仍校验路径、实际大小、CRC 与 HTML UTF-8，拒绝路径穿越、重复/重叠路径、符号链接和特殊文件。预览只编译 HTML 实际引用的浏览器 JS/CSS 依赖，其余文件作为不可执行附件保留；因此与入口无关的 Node 检查脚本不会破坏预览。动态 `innerHTML` / `insertAdjacentHTML` 中的本地图片路径也在进入页面前转换，不依赖外网。
- Vue/React 等工程应连同构建产物上传，入口优先选择 `dist/index.html` / `build/index.html`；选择需要编译的 TypeScript/Vue 脚本时，预览明确指出具体文件与构建要求。没有 HTML 入口的目录会在选择阶段提示缺失条件，平台不执行 npm/Python 构建。外部 CDN、远程 API、自定义 importmap、嵌套页面/插件仍不受支持；请勿上传密钥等敏感数据。
- 元数据与版本保存在 SQLite，源码及上传暂存位于 `${CHAT3D_TEAM_DB}.dashboards`。**备份或迁移须在停服后同时复制数据库及该内容目录**；只复制 SQLite 不能恢复源码。旧版内嵌源码记录首次启动时迁移到内容目录，保留原版本与幂等记录。HTML/ZIP 下载保持原始字节；文件夹下载为服务端生成的 ZIP，保留每个文件的路径与内容。下架只隐藏普通列表，不破坏已有固定版本引用。
- 源码导出显示准备与传输进度；总大小已知时显示实际字节进度，未知时显示已接收字节而不伪造百分比。导出完成、失败与用户取消分别提示，取消不显示成功；浏览器发起下载不代表文件已落盘，仍需检查浏览器下载记录。
- 看板库模板预览可直接「接入当前场景」，确认场景名称和预览的固定模板版本；只接受有可见模型的场景，资产项目不能作为库预览接入目标。无目标时提供场景库入口，未登录可就地授权。不修改未发送的对话草稿或附件。读取、布局检查期间切换场景或账户会拒绝接入，模板下架也拒绝新接入。对话 `/看板` 选择入口保留，复用相同布局与版本绑定检查。
- `/看板 模板名` 默认将当前三维场景融入模板，`/看板 嵌入 模板名` 显式指定相同行为，`/看板 叠加 模板名` 保留以三维场景为主的看板面板方式，`/看板 移除` 撤销当前绑定。模板重名时从列表选择具体版本原件；接入为一笔可撤销修改。读取或布局检查过程中切换了场景、输入或账户会中止，不写入错误场景。工作台「查看看板」读取绑定的精确服务与固定版本，也提供组合 HTML 导出，不自动追随新版。
- 输入 `/` 或 `/看` 显示技能菜单，目前只有「看板」；点击或 Enter 后转到 `/看板` 模板列表。不把技能菜单输入发送给模型。选择模板使用内部固定 ID/版本定位，但输入框保留可读模板名称，重名不会误选；失败后原场景、原绑定和选择文本保留，提示换模板或显式叠加，不再要求用户理解模板 DOM 标记。
- 查看已接入看板时，点击「调整模型」可设置大小（25–400%）、水平/垂直偏移（±100%）、旋转（±180°）和俯视角度（5–85°）。修改仅影响显示，不改场景节点几何；点击「预览调整」后重载预览，不在每次数值变化时重建三维场景。点击「保存显示设置」创建可撤销修改，重新打开、项目 JSON、团队发布及组合 HTML 导出保留设置；关闭未保存的调整则放弃，恢复自动适配后也需保存才持久化。鼠标浏览不会自动改写已保存设置。
- 已接入组合看板的内部画布固定为 1920×1080，外层统一等比缩放；查看窗口按画布比例和屏幕可用空间收窄。库卡片及模板详情只展示独立版本绑定截图，不下载或运行模板；组合预览与离线导出仍使用固定画布坐标。非 16:9 窗口允许留空，内容不拉伸。
- 「编辑三维区域」只显示拖动框与边角手柄，无位置/宽高参数面板。拖动移动、拉伸缩放，聚焦手柄后方向键每次 1%、Shift 每次 5%，拖动中 Esc 取消；点击「完成区域编辑」直接保存一笔可撤销修改。这里调整的是三维窗口区域，和「调整模型」的相机缩放/视角不同。三维层始终在数据面板下面，即使区域扩大到数据面板范围，也不覆盖标题、图表、指标和导航；数据层仍接收点击。
- 融合遵循参考 WMS 大屏的层次原则：去除模型独立标题栏、白底、页脚与额外大灰地面，透明三维视图与模板内容区域融合；保留模型自身材质、交互及模板周围图表/指标/导航。优先使用模板声明的 `[data-scenivo-scene]` / `[data-scene-slot]`，其次识别三维示意区域或真实布局中的可用空白；没有可靠空间时给出明确提示。模板源码与原始导出不因融合被永久改写。
- 场景 JSON、本机恢复、场景库与团队发布保留绑定配置，不携带模板源码或登录凭据。重新查看需要登录绑定所属服务；组合大屏 HTML 则包含当前模板及静态模型，可离线打开，导出后不随模型或模板自动更新，不包含编辑器和动画联动。普通模型 HTML/GLB 导出保持原契约。

### 隔离与边界

上传内容只作为数据存储，不在服务器安装依赖、运行构建或执行源码。预览中的模板与模型使用独立的 `allow-scripts` 沙箱，不允许同源权限、表单提交、弹窗或顶层导航；静态模板还受外层页面与 CSP 限制，不向模板暴露团队 token、模型配置或父页面接口。模板内显示的数据不代表已接通 WMS/MES；真实业务接口、鉴权、字段映射与模型状态驱动需要独立的数据接入契约。

### 实际渲染截图与历史回填

- 管理员操作菜单「管理此版本截图」显示 ID、固定版本和包 SHA-256。须在受控本地/桌面实际渲染该包，核对入口、资源、画面后拍摄 PNG，填写渲染环境/来源与拍摄时间，明确勾选人工确认。不是自动截图功能；服务器不执行上传 JS，不要求 Playwright、浏览器集群或截图服务，也不能自动证明像素确实来自模板。
- 接口：成员可读 `GET :id/:version/screenshot/info`（旧版本首次按需计算保留包的指纹）；管理员 `POST :id/:version/screenshot` 上传及绑定，`POST :id/:version/screenshot/unbind` 取消绑定。写操作重新校验当前角色。上传包含 `packageHash`、`expectedScreenshotId`（无图为 null）、`base64`、`source`、`capturedAt`、`confirmed:true`，不接受图片 URL。绑定使用 compare-and-swap，防止并发覆盖；新模板版本不继承旧截图，旧版本截图仍可读取。网络失败可能是结果未确认，重新打开核对绑定后重试；不把未确认请求当成功或已取消。
- 只接受不超过 8 MiB 的非交错、非动画、8 位 PNG，宽高 320×180 至 7680×4320、像素数不超过 16,777,216。服务端检查签名、结构、尺寸、受限解压、CRC、完整解码并重编码，剥除元数据/附带内容；拒绝 SVG、脚本、外链、非图像与损坏图片。上传 JSON 单请求上限 12 MiB。文件读取期间可取消，未发送请求；原子保存阶段禁止伪装成可撤销的传输取消，完成后可显式取消绑定。
- 包 hash 是 `SHA256(JSON.stringify({entry,sourceKind,fileName,files}))`，files 按路径代码点顺序，含 path、size、每个原文件 sha256；HTML/ZIP 按原文件字节，目录按每个文件字节。发布时保存；旧版只在管理/查询截图身份时按需计算，不在普通列表扫描全包。
- PNG 净化只用 Node 内置 zlib，不新增部署依赖；支持灰度、RGB、灰度+Alpha、RGBA 四种 8 位像素，逐行解码全部五种过滤器后重编码。索引调色板、tRNS 透明色表、交错或 16 位 PNG 请先在本地图片工具转为标准 RGBA PNG；不会静默修改透明色表语义。
- SQLite 新增包 hash、截图审计记录和当前绑定表；PNG 存于 `${CHAT3D_TEAM_DB}.dashboards/screenshots`。记录来源、拍摄时间、确认人、创建时间、尺寸、包 hash、净化后图片 hash。取消/替换只切换当前绑定，保留审计记录与图片，不删除旧模板或原包；需把截图目录纳入原有停服整体备份。未提供自动保留期清理。
- 历史六模板可逐条补图，不要求重发源码。默认离线工具：`node scripts/dashboard-screenshot-backfill.mjs /本地路径/manifest.json`（可显式 `--dry-run`），只读取清单/图片、校验并打印报告，完全不联网不写库。清单每项：`{templateId,version,packageHash,screenshotFile,source,capturedAt,confirmed:true,expectedScreenshotId:null}`；图片相对清单路径。dry-run 的包 hash 是人工清单声明，不能证明与库一致。只在获准的本地副本演练时用 `DASHBOARD_BACKFILL_BASE=http://127.0.0.1:端口 DASHBOARD_BACKFILL_TOKEN=本地管理员令牌 node scripts/dashboard-screenshot-backfill.mjs manifest.json --apply`；工具拒绝远程服务和重定向，apply 会先核对固定 ID/版本/hash/当前绑定，再调用正式接口。此轮禁止执行真实历史回填或生产读写。
- 已知线索仅为当时 v1：蓝色仓库 `c2d59e92-afb5-4c77-803a-3c84d667746a`（51 文件、5038487 B），深色看板 `9f5cf0e6-2ddf-483f-afb1-4234d0da04c2`（43 文件、4578675 B），入口 `index.html`。这不是当前远程 head 的证明，也不充当包 hash；其余四项需由已授权的本地资料核对，不猜 ID/版本。父代理桌面实拍交付后再填写真实文件路径和来源，不用参考图补齐。

## 使用

1. 点击全局账户、团队库或看板库的 **登录授权**，在协同平台完成授权后回到原窗口。资产、场景、发布和获取共用登录状态；模型 API 仍单独配置。
2. 浏览团队网格/列表，搜索名称和说明，按“已关联本地 / 可更新”筛选。可见卡片自动显示对应固定团队版本的真实预览；点击图片或标题查看详情。可以多选资源并一次确认获取，列表显示逐项成功、失败与重试结果。团队页不再重复显示账户栏，退出使用全局账户入口。
3. 本地资产库或场景库的详情及批量操作可直接 **发布至团队**，不再先跳页从底部长下拉框逐项找内容。仅已保存内容可发布；未保存场景、待确认预览和运行中的任务必须先处理。
4. 点击“准备发布”固定选中内容，核对“新增到团队库”或“更新团队版本 vN”后确认；新增不会覆盖本地资产，更新会追加不可变团队版本。准备阶段不上传，之后的本地修改也不加入本次发布。弹窗仅保留资源、发布位置、上传大小、进度、耗时和结果，账户与冗长说明不重复展示。失败重试复用同一请求标识，已成功项不会重复发布。
   发布位置按精确服务、资源类型和团队原件 ID 匹配本地版本关联，不按名称猜测。已有来源默认选择有权限的关联原件；缺失、跨服务或多重关联要求明确选择，不能静默新增。团队原件已从本地基线更新时，准备发布会拒绝：先获取新版再编辑，或明确新增为另一原件。其他端在准备后抢先发布仍由服务端版本冲突拒绝，不覆盖历史。
5. **版本关联**记录精确团队服务、原件和固定版本，以及对应的本地资源。发布和获取后显示关联版本；“检查团队更新”只查询版本，不自动上传或替换个人内容。
6. **获取新版并保留旧副本**始终新建独立本地资源：原来的资产版本、场景、手动修改和未确认草稿保持不变。相同团队固定版本再次获取会复用已关联副本，不无意创建重复项；本地副本被删除时先恢复旧副本。场景中的固定资产引用不会自动升级。
7. 批量传输显示逐项结果，只重试失败项。获取结果标明本机资产库 / 场景库、本地名称和固定版本 / 修订，点「在库中定位」仅显示本次成功结果；不自动切换正在编辑的项目。相同版本复用既有副本也可定位，本地修改保留。服务端拒绝旧版本追加时需重新准备，不能覆盖他人更新。关闭不撤回已完成的发布。

“准备发布”在 Web Worker 中逐项读取已保存的固定资产、校验公开字段、生成兼容的内容指纹、序列化并无损 gzip 压缩请求；场景用有确认的有界分块传给 worker，不在主线程重复复制整份几何。对话框显示实际准备/压缩阶段、数量和耗时，期间禁止改选/关闭/重复提交。压缩包以可转移二进制返回主线程，确认及失败重试复用同一包与原发布标识，不重新序列化或混入后续修改。浏览器必须支持 Worker；准备失败明确报错，不回退到主线程长时间计算。

桌面和浏览器均将 gzip 发布包分成最多 1 MiB 实际数据块，经 `/api/team/publish-uploads/start`、`/:id/chunk`、`/:id/complete` 上传，每个 Base64 JSON 请求最多 2 MiB。界面大小与字节百分比对应压缩包，只累计服务端已落盘确认的字节；全部接收后显示“服务器处理中”，成功回执及本地关联保存后才显示“已发布”。团队内容、完整请求展开及压缩包各限 500 MiB，服务端有界解压拒绝损坏包和解压炸弹。整次传输限 15 分钟；权限、固定版本、乐观并发与公开字段校验不变。断线显式重试从确认偏移继续，不自动重传、不在旧服务缺少 gzip 分块接口时退回超大 JSON 请求。

部署同时更新前端、`server/team/service.mjs`、`server/team/publishUploads.mjs` 及 `dist-team/validator.mjs`。代理转发整个 `/api/team/publish-uploads/`，允许至少 2 MiB JSON 和 900 秒最终处理超时；保留旧发布接口时采用 512 MiB 代理配置。SQLite 自动增加 `publish_uploads` 表，未完成数据位于数据库路径后缀 `.publish-uploads` 目录；成功后清除暂存文件、保留幂等回执。恢复未完成上传需保留数据库和该目录。上传绑定账号、标识、总字节及摘要；更改同标识内容、跨账号访问、损坏块均拒绝。来源白名单、TLS、权限不变。截图中的 `Failed to fetch` 无法单独证明线上代理配置，生产部署后仍需核验。

团队发布仍是完整几何、材质和可选动画快照，不包含聊天、模型密钥或生成历史。关联保存在独立的本机数据库，不包含 token；个人工程/备份格式保持不变，资源备份不迁移团队写入关系或账号。关联不是自动同步、实时协作或团队质量认证。

发布同时携带一级或两级的分类名称路径（例如“设备 / 叉车”），不把客户端内部分类编号当作服务端目录名。资产和场景的分类分别管理；发布准备时固定当前名称与层级，团队桌面页及 `/team/` 门户显示该路径并支持分类筛选，选择一级分类会包含子分类。获取固定版本或下载后导入时，在对应的本地分类树中匹配相同父级下的名称，不覆盖已有名称和其他资源。重命名本地分类不会追改已发布版本，需要发布新版本才能更新其分类快照。

团队服务启动时为旧 SQLite 版本表增加分类路径列，并仅从旧资产中可识别的人类分类名称回填一级路径；旧场景没有分类来源、或旧资产只有内部 `category-UUID` 的，显示“未分类”，不猜测标签。旧模型、固定版本、发布标识和重试摘要均保留。客户端、Node 团队服务及 `dist-team-web/` 门户须一起更新；只重装桌面包不能让旧服务返回场景分类。升级服务前备份数据库，启动后自动迁移，原数据库路径和账号配置保持不变。

预览只读取卡片所标注的团队原件及固定版本，不借用本地关联副本。优先复用该团队资产快照内经过格式校验的缩略图；没有缩略图的资产和场景沿用真实缩略图渲染器，不调用生成模型。可见卡片按队列串行读取和渲染，离屏、切换类型、服务、账号或关闭页面时取消待执行任务并丢弃过时结果；预览缓存只在当前团队页会话内保留，不写入个人资源库。读取、解析、图片显示或渲染失败时明确提示并提供“重试预览”，不显示伪模型或本地旧版本图片，获取和发布仍可独立使用。软件几何预览不代表材质、光影或人工验收。团队服务维持不可变版本和乐观并发检查，不需要部署新的同步服务器。

## 运维与边界

- 备份：停止服务后复制整个持久目录（含 SQLite、WAL、SHM）；恢复到受限目录，保持相同 Node 版本后启动。在线备份须使用 SQLite 的备份工具，不要仅复制正在写入的主文件。备份含密码哈希与有效会话，应按内部敏感数据保管。
- 限制：单进程服务，单团队，没有实时协作、外部客户租户、发布撤回或在线用户管理。登录主路径是 **登录授权**：打开协同 SSO 页 `{SSO_UI}/#/sso?client_id=scenivo&redirect_uri=…&response_type=code&state=…`（**hash 路由** `/#/sso`，勿用 path `/sso`；不传 `scope`，避免协同自动授权跳转，等待用户点击同意授权或拒绝）；默认 SSO UI `http://pm.jiezi365.com:48001`，API `http://36.133.218.210:48080`。回调 `/team/sso/callback` 带回 code 后服务端 `/api/team/login/sso/code` 兑换。新账号为 member，已有账号保留角色；停用账号与平台 401 均拒绝。SSO 会话超过 5 分钟或发布时会用同一用户 token 复核 `get-permission-info`，平台 401 删除会话。本地团队密码登录默认隐藏，仅 `VITE_CHAT3D_TEAM_SHOW_PASSWORD_LOGIN=1` 调试展示；服务端可用 `CHAT3D_TEAM_PASSWORD_LOGIN=0` 关闭。单次发布的 HTTP 请求体上限为 500 MiB，团队格式校验上限为 500 MiB。容量规划与磁盘配额由部署方管理。
- 团队登录失效后，工作台右上角会显示独立的警告图标。点击可重新授权；本地项目的编辑、保存和导出不受影响。
- 防护：服务端认证、数据库事务、不可变版本、逐原件写权限、跨源白名单；登录错误累计8次暂时限流15分钟。生产代理还应限制连接与登录速率。TLS在公司反向代理终止。
- 测试仅创建临时账号与临时数据库，不触及真实个人数据、不调用真实收费模型。

## 验证与 Windows 交付

```sh
npm test             # 原有完整回归
npm run test:team    # SQLite/HTTP、桌面团队页、Web 导入包与 /team 静态路由测试
npm run build        # TypeScript、前端、Worker、团队校验器构建
```

`.github/workflows/windows-desktop.yml` 在 main 推送后先运行上述回归，再打包 **0.2.1** Windows x64 NSIS，并调用安装测试。每次制品都记录本次提交 SHA、工作流 ID、版本和 SHA256；安装测试校验这些字段与安装后的 ProductVersion，再执行现有可访问性/UI 操作。安装包与 `windows-installed-smoke-{sha}` 包含原始证据。该流程不代表用户 GPU 或公司实际 HTTPS 部署已经验证，也不能用旧0.1.3结果替代。本次 CI 结果与链接见交付记录。
