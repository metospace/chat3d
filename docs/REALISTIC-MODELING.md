# 写实生成与实时渲染

直接生成使用现有 Three.js，不需要安装 Blender，也不访问外部纹理服务；Blender 生成使用用户授权的本机 Blender。两种生成方式共用[通用建模标准](MODELING-STANDARD.md)：默认真实可信、结构完整、材质有据的高质量模型，覆盖有机体、自然物、产品与完整场景，不默认玩具化或基本体拼装。用户明确的卡通、低模、参考风格及保留要求优先，仍须保持约定完整性与形体、材质一致性。

- 首页和工作台生成菜单只选择“直接生成 / Blender 生成”，不设快速、普通或精细质量档位。细节按对象在目标画面中的可见尺度分配，预算不足保留未完成草稿，不降低质量目标。
- 直接生成使用 Three.js 建模与可编辑网格链路；桌面 Blender 生成通过本次会话授权的原生链路执行本机程序，无需另开 Node 服务，Web 仍需明确启用本地适配器。生成方式不改变已有模型；执行中锁定本次选择。
- 共用规则先检查轮廓比例、次级体积与负空间，再检查适用的结构/解剖/植物关系、材质和相关精细特征。倒角、厚度与连续曲面按材料和对象判断，不强加统一毫米数、统一圆角、噪声、磨损或隐藏机构。已有资产仍需看实际结果；目录名称、零件数和多边形数不等于质量。
- 视口的“显示 → 灯光效果”可切换写实棚拍与经典展示，选择保存在本机。灯光不会写入模型材质，也不会重建场景。
- 新增的默认喷漆、裸金属、玻璃与工装材质使用不同的物理参数。程序纹理是本地生成的细微法线与粗糙度变化；已有项目中同名材质保持原值。

项目 JSON、局部外观修改、GLB 导入导出和离线 HTML 支持 `clearcoat`、`clearcoatRoughness`、`transmission`、`thickness`、`ior` 五个物理材质参数。厚度单位为米。GLB 中高级材质扩展的额外贴图仍需先转换为当前支持的标准贴图，不代表支持任意 Blender 节点材质。透射玻璃不参与不透明对象的实例合批，也不投射实心黑影；当前没有模拟玻璃焦散或彩色透射阴影。

离线 HTML 内嵌室内环境生成器与导出时选择的灯光参数，支持环境反射和阴影，无需加载远程资源。GLB 保留模型与材质，查看器自身的灯光与色调映射会影响最终观感。

## 共用标准与不同复核链路

复杂多参考图单体的直接生成，在主形从 `silhouette` 进入 `detailed` 前会额外进行独立图像对照。对照只接收用户要求、原参考图和当前互补方向截图，只核对主体轮廓、比例、曲面起伏与关键负空间，允许灰模和未制作的饰件。复核确认存在差异或证据不足时暂停细化。复核请求未完成或返回不可读时，沿用已有的本轮多视角检查与几何校验继续细化，保留最终独立复核。构建与局部源码补丁使用同一规则。

主形对照结果按场景版本、组件、检查阶段、参考及需求缓存，实际修改后重新获取证据。细化后的最终参考对照重新检查完整特征和材质。复核重试仍未返回有效结论时保留细化结果并标记为未完成。后续可重新复核当前草稿，复核通过时可以更新预览状态，无需修改几何。独立对照仍由模型判断，自动化用例验证的是流程行为。

通用提示核心位于 `src/ai/generationStyle.ts`；Blender 的 `src/ai/blenderSkill.ts` 复用同一核心并补充 bpy、材质与导出要求。规则不新增几何工具、外部资产服务或自动质量认证；当前链路做不到的必要特征须说明限制并保留未完成，不能把写入提示词视为已实现。

直接连续建模保留数据守卫、当前版本多视角证据、六项自检及人工确认；单次兼容与隔离数据生成仍是未经视觉验收的数据草稿。人物手部、软件图材质限制、UV 与真实接触检查不因通用标准而放宽。相机应看清当前差异，隔离近景不能证明场景关系；证据不足保持待核对，不新增固定四视图或无限审计。

应用不设建模任务总时长、请求总轮数或累计 Token 上限，也不向模型服务指定单轮输出 Token 上限。模型服务仍可能有自己的限制，并按实际用量计费。手动停止、模型连接无活动保护和直接 Agent 的无进展停止条件不变；本地 Three.js 脚本执行不受模型连接的无活动计时约束。

多部件组件或自定义网格新增、改形时，直接 Agent 须取得当前版本、实际送达模型的互补视角，并引用当前部件明确核对外形比例和必要结构；同轴正反面不够。全场图只有在一个组件就是全部可见几何时才能充当该组件的形体图。现有图组会按需补互补方向，已归档图可原样召回。缺图、缺结论或有明确缺陷时保留阶段草稿，不以部件数、结构绑定或一句总评代替。

外形或结构审查中的明确失败会加入现有形体修复单。改色、重命名和省略问题不能解除；修改所指部件后还须用当前版本的原方向证据复核。仅摆放固定资产或仅改材质仍用原复核范围，不额外要求这套形体核对。

Blender 在本机生成同版 BLEND、GLB 与真实 PNG，PNG 返回模型后在后续轮次记录可见观察；明确缺陷通过局部脚本补丁修复并重新渲染。该路径不额外运行直接生成或其完整六项提交守卫，单张图已复核不代表背面、被遮挡区域或工程质量已通过。桌面原生授权不随配置保存，Web 适配器须自行明确启用；任意 Python 执行风险见[本地适配器文档](../server/blender/README.md)。

Blender 优先从现有渲染检查主体轮廓、主次体积和开口，再看材质和细节。前版明确差异随新版候选返回；遇到仍有明确问题却只用文字结束时，最多补两次继续修正的机会。同一候选不允许直接清空已确认的问题。此路径仍只有一张 Blender PNG，不冒充直接生成的互补视角验收。

脚本补丁保留未涉及的源码，但每次在空工程执行完整脚本，不是几何范围隔离，也不包含工作台手动编辑；随机生成可能影响未改源码对应的结果。原生 Blender 节点不保证能由 GLB 和主画布完整重现。Blender 本机 Python 适配器的脚本大小、进程超时和截图传输约束仍适用；受阻时如实保留有效候选与未完成项。


## 参数化构建流程

Pi 连续建模新增 `build_modeling_program` 和 `read_modeling_program`。参考图任务默认可编写 Three.js 函数体，运行时提供 `THREE`，返回命名 Group/Object3D；曲线 Shape、ExtrudeGeometry、BufferGeometry、管线及 PBR 材质直接转换为独立可编辑网格，不执行外部文件或导出脚本。源码保存在项目节点元数据，不会在打开项目时自动执行，也不会自动反映后续手动编辑。

执行使用无同源权限的 sandbox iframe 与独立 Worker，CSP 禁止网络。Three.js 参数化源码不设长度上限，也不设固定执行超时；用户停止或离开页面会终止 Worker 并释放资源。生成不单独限制输出字节、网格、顶点、索引或材质数量；结构化建模也不按展开零件数截断。结果必须通过几何校验并能写入现有 400 MiB 项目文件格式，不自动减面。骨骼、实例、外部贴图与自定义着色器仍明确拒绝。脚本只接收本次源码和 Three.js，不接收模型密钥、项目数据或聊天。

构建完成仍走原有草稿、编辑范围、尺寸与真实截图复核。先构建主轮廓再看图修正，后补用途细节；绑定仅表示实际部件存在。整体重建必须明确组件 ID，并原子替换；带动画、连接、关节或资产关联的组件须使用保留节点的局部编辑，禁止整体重建丢失关系。局部选区与位置锁不会因脚本放宽。

参数化构建必须明确stage：silhouette是同一任务的中间剪影，不能直接提交完成；detailed要求完整方案的全部特征关联到实际返回部件，仍不证明视觉质量。剪影之后必须继续补对象所需的次级体积、结构/解剖/植物关系、接触、材质分区与相关细节；仅在实际涉及机构和操作界面时补足对应部位，不能因提速只交主体框架。已有旧项目没有阶段字段时保留原语义，不按部件数量猜测阶段。

不使用参考图自动像素打分、独立中性形体门禁或强制 GLB 回读。互补取景复用普通检查图；外形和必要结构的结论仍由模型依据实际画面记录，不等同于参考相似度评分或人工验收。

`tests/generation-quality.mjs` 用车辆、工业设备和有机体的流程夹具覆盖互补取景、明确结论与改形复核；`tests/blender-direct.mjs` 覆盖携带前版问题、文字提前结束后继续修正和同版拒绝清空问题。固定回复验证的是流程，不代表实际模型造型成绩。

明确缺陷与结构化参考差异仍驱动当前授权任务继续局部修复，即使本轮尚未编辑也不应只报告问题后结束。文字提前结束最多获得两次无有效进展的恢复机会，仍尊重用户停止和只检查权限；缺少必要资料时保持未知，不猜测几何。`tests/autonomous-repair.mjs` 覆盖该自动修复行为，固定模型回复不代表实际生成质量。

名称、分类及设计关联只在 `visualFingerprint` 完全相同时延续证据：归档像素与原始 revision 不改写，当前投影标出 effective/original revision，metadata 链之后允许召回同一像素。真实几何、材质、布局或动画变化没有这种别名，旧图仍过期。首次实际送达的归档页计为有效进展，反复召回同一页不计。


### 源码和复核提速

`read_modeling_program` 使用互斥 selection：`{mode:'summary'}` 目录、`{mode:'lines',start:1,end:24}` 行、`{mode:'characters',start:0,end:3993}` 字符、`{mode:'search',query:'函数名'}` 字面搜索。不要混用模式或把返回的窗口元数据当作参数；`nextChar` 用于字符或搜索续读。读取分页最多 120 行 / 12000 字符，不限制整份源码或 `patch_modeling_program` 的单段查找或替换文本。过期、匹配歧义、交叠、无变化和越权重建仍会拒绝。

参数化重建与中断恢复从已应用的同方案替换记录迁移形体差异：同组件中名称唯一的对应零件使用新 ID，保留原差异和几何基线。旧 ID 下的报错会给出已确认的新绑定；名称有歧义时不猜。仅重建并换 ID 不能解除问题，仍须修改实际形体并用当前视角复核。生成脚本运行错误保留上个有效草稿；浏览器提供源码位置时，工具回执带脚本行列号供模型修补。

工具组使用groups数组一次启用，disableGroups收回不再需要的参数；核心取景与脚本工具无需额外启用。所有取景回执携带reviewReadiness，列出真实组件/部件引用、当前视角和提交范围，便于下一轮合并细节与整体复核。不可用、过期或同轮证据仍不能通过，未知与实际缺陷不能被清空。上下文只删除被替代的同版本视角，不删除原参考图或不同视角的有效证据。
复核可按标准分次补齐，同一组件当前版本的有效结论合并，未提交项保持unknown而非通过；已知fail保留。补充不绕过真实证据、节点引用、隔离关系和软件材质限制。底层完整复核验证仍要求六项，不完整直接调用会明确列出缺项。

### 统一命令契约与失败兜底

全部18种公开AI编辑命令由`src/ai/commandContract.ts`单一注册表提供Schema、必填字段、组合约束和参数报告；连续代理、单次生成和失败批次纠正共用。完整检查所有操作及嵌套参数，一条无效则整批拒绝，不跳过坏命令部分执行。未知命令不猜映射；显式错误的向量、枚举、布尔值及材质不降级替换；合法省略的创建变换等默认行为保留。数值使用JSON number，数字字符串不接受。动态节点/材质引用、依赖顺序及动画关系仍在原子应用阶段校验。

SDK执行前拒绝的批次也进入同一字段报告和缓存。模型内部用原failedId及path补齐可确定字段；若提前文字结束，最多追加两轮自动纠正。用户新要求、只提问、取消和版本变化仍优先；不自动重试网络请求、不降档模型、不用占位模型兜底。无法恢复时普通界面只显示保留结果和下一步，原始错误留在脱敏任务活动诊断，不要求用户理解指令或参数。单次兼容生成保留原来一次纠正机会，并返回完整契约错误供内部纠正。

`tests/command-contract.mjs`覆盖全命令有效样例、必填字段矩阵、嵌套错误、整批拒绝、一次多字段纠正和可撤销事务；`tests/generation-fallback-browser.mjs`验证真实界面遇到服务失败保留原预览、无原始技术错误且不重复请求。模型响应仍由固定回放提供，不是实际模型永不失败或质量保证。


这些机制减少重复传输与协议往返；未进行同提示词付费模型计时对照，不承诺固定提速比例。主体比例、外壳曲率与操作件层次先于微细字标完成，不以细分数和零件数代替质量。

### 差异驱动的场景修正

连续建模可先用`capture_quality_review({overviewOnly:true})`定位差异，再记录真实目标、修改动作与复查视角；明确缺陷优先实际修改，不把所有组件取图和六项表格当作串行工序。`componentIds`每页指定1–2个本轮受影响组件，复查自动加入未解决参考差异声明的视角；最终仍执行原有全景、范围、动态与缺陷提交守卫。`read_scene_contract`只读当前共享布局、主要材质、比例方案和组件源码目录，用于局部修改时保持一致，不会自动重涂或改布局。

每轮模型上下文最多携带6张生成检查图，用户参考图不受此限制。本次运行原始检查图按captureId不可变归档，`recall_evidence`可列目录和每次取回最多3张原图；不会重新渲染或增加验收权限。过期版本不能取回作为当前证据，隔离、软件和动态限制原样保留。只有实际送达模型的视角才能支持细节通过或关闭形体差异；动态样本必须全部送达。归档可用不等于已看过或已验收，原始模型与工具记录不因上下文分页被修改。

验证`tests/evidence-context.mjs`、`tests/repair-agenda.mjs`、`tests/repair-workflow.mjs`覆盖超过16张原图的分页、取回、局部真实数据修改和未解决差异。真实WebGL三组件回放完成全景→记录差异→修改一个组件深度→同向近景复核，其他组件/材质不变；模型回复由固定回放提供，不是付费模型重新生成的质量或耗时成绩。



验证：`node tests/modeling-program.mjs`、`node tests/modeling-program-draft.mjs`；真实浏览器隔离检查使用 `node tests/modeling-program-browser.mjs`。本次以用户提供的 Codex 原始参数化源码验证 641 个可编辑部件、24864 个三角面、14 种材质及离线 HTML；这是源码执行与保真链路验证，不是重新调用模型看同一参考图生成的质量成绩。
