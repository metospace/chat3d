# Project and modeling workflow redesign

The home is an AI-first conversation starting point: a centered idea composer precedes recent work, with direct model/scene selection. Its bottom toolbar keeps the icon-only attachment action, quality picker and model picker together on the left and generation on the right, with no expand step or separate settings row. Long model IDs truncate without shrinking the generation button; narrow layouts retain one aligned row. Promotional headings, example prompts, type descriptions and the recent-work tagline are omitted. Blank creation and GLB import stay secondary. Recent artwork cards use 4:3 previews, a full-card open action, status and update time; their separate menu renames projects without editing model data or conversation. New projects derive a short subject title from the idea, while manually named projects retain their names. Active tasks appear as compact rows below the composer; empty task panels are omitted. The sidebar owns library navigation. Local/team boundaries and explicit generation authorization are unchanged.

Project and resource grid previews share the renderer’s 4:3 ratio and fill their media frames without square letterboxing. Visible project drafts with geometry but no saved thumbnail receive a transient local preview through the isolated renderer or geometry fallback. Preview requests are serialized and cancelled on unmount, do not call a model/server, and do not change workspace content, saved thumbnails or acceptance status. Empty projects remain explicit placeholders.

The model connection dialog keeps the endpoint, key and searchable model picker in one compact form. Model refresh is secondary; address help is available on demand and credential retention remains an explicit opt-in with its local plaintext warning. Advanced execution controls remain collapsed. Select search inputs retain their native transparent background so selected model names stay visible after blur, including long IDs. Changing the endpoint still clears the key and invalidates stale discovery results.

The model picker uses a viewport-bounded panel with fixed search/header/footer and a separately scrolling model list. The current row is brought into view on opening. Its strength button opens a side menu with default, low, medium, high and extra-high (`xhigh`); the same preference is available in connection settings. This is separate from fast/fine modeling quality. Explicit choices persist and send `reasoning_effort` in connection tests, single-call generation, Pi turns and parallel child requests, using the task's configuration snapshot. Default omits the field. The service must support the selected value; errors do not trigger an automatic retry or lower strength. The setting applies to subsequent requests and is not a provider capability claim.

Each mounted model picker retains the successfully discovered catalog for the exact endpoint/key pair. Reopening or changing reasoning effort does not refetch or clear it; explicit refresh does, while a failed refresh keeps the prior catalog usable. Endpoint/key changes never reuse another connection's results, and late/aborted responses are discarded. While initial discovery is pending or fails, the configured current model remains visible and its reasoning control stays usable; no alternative IDs are invented. A separate non-shrinking strength badge beside the model name and the panel footer reflect the saved choice even after the popup closes. Catalogs are memory-only, not persisted with credentials. Slow upstream discovery itself is not made faster by this UI change.

The editor uses a CSS grid with a left panel rail, navigator/inspector, canvas and independent assistant. The top header separates project identity, undo/redo, view tools and document actions, with consistent 32px controls; export and save stay together, and the assistant has a compact panel toggle. Narrow screens move view controls into the canvas and keep the assistant below it. Scene editing actions remain a centered, horizontally scrollable toolbar. The assistant no longer repeats the project title or scene object count, large welcome cards or library links: its empty state has one hint and at most two context-aware examples that only fill the composer. Connection guidance stays beside the model picker in the input area. Task records and resource details open on demand without replacing the current draft.

The transcript preserves Bubble.List’s reversed scroll container so its native bottom coordinates remain correct. Sending follows the latest messages after rendering, while manual history reading pauses following until the user returns to the latest content. Current selection is explicitly labeled and its meaning is distinguished from modification scope.

Instruction scope appears above the composer when the scene or pending preview contains objects. Its single dropdown also owns placement locking, whose active state is shown beside the instruction context. The sender footer only offers reference reuse when historical attachments exist and no new attachments are attached. Highlighted objects remain referential unless selected-only scope is explicitly chosen. During generation, sending adds a message to a compact queue above Sender. Each message has inline guidance, delete and more actions; guidance explicitly promotes it into the current task and requires an available agent control channel. Unpromoted messages stay queued until the user prepares and sends them. Applying a preview remains explicit and undoable.

The compact confirmation card is placed over the canvas, showing actual added/modified/removed object counts, before/after comparison and apply/continue/discard actions. Outstanding checks and the object change list open in an on-demand drawer. Checks retain the original issue text, group it with practical inspection guidance, distinguish reported differences from unknowns, and expose reference images and object location when available. The drawer leaves the canvas interactive. Preparing a check instruction fills the composer without sending a request or replacing an existing draft; applying never marks visual quality as passed. The task center can inspect another project's store without activating that project; only entering it changes the active project.

Outstanding checks use `qualityIssues` as the authoritative source, including an explicitly empty list; only legacy batches without that field fall back to summary issue text. Semicolons inside an issue remain intact, and repeated identical entries display once. Missing evidence and uncertain observations remain unverified, not reported defects. A submitted round can still have outstanding quality checks: these no longer set `incomplete`, which is reserved for unfinished stage drafts. Completing a continuation does not append an unconditional warning from the earlier partial stage.

Running drafts expose the authoritative planning/building/reviewing/repairing phase separately from waiting for or receiving model content. The canvas, conversation trace and task panel show the age of the last visible model change; planning and feature-binding metadata do not reset it. Review explicitly explains that checking images need not change the displayed model. Elapsed time alone never declares a stall or a percentage complete. Diagnostic exports whitelist the phase and numeric last-change timestamp without adding raw text or geometry.

Empty ready canvases use a centered creation state rather than an unlabelled grey viewport: idle projects offer composer focus, GLB import and the asset shelf; an active task with no returned geometry shows its current phase, a task-record action and a reminder that the first model will appear automatically. Empty canvases omit the zero-part badge and inapplicable transform toolbar. The overlay disappears as soon as the displayed draft contains nodes, without applying it; renderer-error notices and active asset placement remain unobscured. Layout and theme use the existing semantic tokens, with a compact narrow-screen variant and no fabricated progress percentage.

Both model paths share a task and response contract covering target, scope, continuation, preview authorization and concise user-facing summaries. Reference-image instructions require silhouette/proportion checks before surface detail, distinguish occlusion from missing geometry, and keep interrupted or unverified drafts separate from successful reconstruction. These instructions improve the workflow; they do not by themselves establish geometric or visual similarity for an individual generated model.

Validation: `tests/product-structure-browser.mjs`, `tests/pro-v6-browser.mjs`, `tests/task-center-inspection.mjs`, and the existing chat, library metadata, project and conversation regression suites. Browser fixtures use synthetic local geometry and do not call paid model endpoints. Screenshots are under `artifacts/product-structure/`.

The canvas asset shelf filters by hierarchical category and searches within that filter. Native asset dragging uses a transient local token and fixed-version reads, displays a ground-projected ghost, and commits one undoable whole-instance import on release. Escape, outside drops, stale contexts and editing locks prevent insertion. The grid scrolls above a pinned footer; keyboard Enter retains the pointer-placement alternative.

Preview submission rejects explicitly reported defects, current failed detail checks and measured requirement mismatches. Clearing issue text without changed model data or fresh evidence does not resolve a recorded defect. Known-blocker text-only endings receive at most two repair continuations within the existing task budget; persistent failures retain a partial draft. Unknown evidence remains unverified rather than being forced to pass. Animation review supports 3–6 selected phase times (including zero) and alternate camera views. Conversation and task labels distinguish previews and unfinished drafts from task completion.

Reference reconstruction now uses a dedicated compact instruction path rather than combining the full scene/catalog manual with repeated acceptance prose. Catalogs, layout and occlusion diagnostics are exposed on demand for reference tasks; `enable_modeling_tools` can restore each group. Existing text-only workflows retain their catalog/layout tools. Tools and prompt size are operational costs, not fidelity scores.

Reference tasks request a coarse silhouette/major-part pass before fine details and surface work, with same-direction and side evidence used for actionable shape repairs. This is a modeling instruction, not automated image similarity measurement. `review_model.detailReviews` can atomically validate and record a batch of component checks alongside global observations and optional completion; invalid rows do not partially write audits, and all existing evidence, known-defect, requirements and submission guards still apply. A single component covering every visible model node can reuse its two or more subject views as whole-scene evidence instead of taking duplicate overview frames; multi-component and interaction evidence remain scoped.

Changing per-turn budgets and repair state are appended only to the outbound context, rather than rewriting the system prefix every round. Superseded successful plans, identical reports and obsolete quality snapshots are compacted without changing the stored transcript; original user images, current plans, target IDs, unreviewed sibling views and errors remain available. A repeated-check receipt never supersedes its authoritative report. These changes reduce redundant protocol work; they do not establish a measured speedup, cache hit rate, or reference reconstruction fidelity on a paid model.

`sectionLoft` constructs one capped continuous solid from 2–32 Y-ordered sections. `roundedRectangle` sections carry center, width, depth and cornerRadius with 8–64 perimeter samples (a multiple of four); `polygon` sections carry corresponding simple contours with equal point counts and winding. Validation rejects crossing/degenerate intermediate strips and precision collapse rather than simplifying the shape. The renderer, bounds, parser, project/asset/team serialization, undo/redo and GLB export share this geometry. Existing elliptical `loft` remains unchanged; constant-profile `profileSweep` is not a substitute for a smooth tapered shell.

Object blueprints can declare `referenceProportions`: two bound feature world-axis extents, an expected positive ratio or null, source (`estimated`/`user`), relative tolerance, view and observation. New reference-based structured creation requires this planning before geometry. Reports recompute actual vertex-world bounds after edits, retain unknown observations and block normal completion for declared mismatches or unmeasurable bindings. Matching an estimate proves only plan consistency, not pixel similarity; perspective/occlusion uncertainty must remain explicit. Legacy plans without this optional field still load.

`review_model.referenceDifferences` records actionable shape defects with stable IDs, target nodes, observation, expected relationship, repair action and view. Omitted fields do not clear them. Resolution requires changed target geometry/placement, a fresh current-version image in the declared view and explicit `resolvedDifferenceIds`; renaming or recoloring cannot substitute. Pending-preview continuation retains these repair records. The agent can replace the incorrect feature rather than decorating around it; normal preview submission remains blocked while defects are unresolved.

Diagnostics v1 adds a launch snapshot of quality, reasoning effort, normalized task budget and numeric reference-image metadata, plus fixed tool failure categories. Export still excludes raw errors, tool arguments, prompts, scene/image contents, URLs and credentials. Validation uses `tests/section-loft.mjs`, `tests/reference-proportions.mjs`, `tests/reference-repairs.mjs`, `tests/reference-agent.mjs` and `tests/execution-telemetry.mjs`. Synthetic model/capture fixtures establish behavior, not real reconstruction fidelity; manual geometry comparisons are capability demonstrations only.

HTML export on desktop requests a native destination before constructing the viewer. Cancelling skips generation; the frontend receives a window-bound one-use destination token rather than writable path authority. Commit transfers raw UTF-8/binary bytes instead of a JSON number array and reports a path only after write and sync succeed. Generation or commit failure releases the pending token, which also expires and is cleared when its window closes. Desktop binaries must be rebuilt for the new command protocol.

HTML construction yields between geometry batches and reports geometry, texture, packing and saving stages. Identical immutable geometries share a serialized buffer while mesh names, transforms and materials remain independent; no vertices are simplified. The exported page remains fully offline. `tests/html-export.mjs` and `tests/export-file.mjs` cover model fidelity, resource cleanup, cancellation and destination-before-generation ordering. Native unit tests live in `src-tauri/src/export_file.rs`.

Structured generation aggregates independently discoverable part, feature-binding and geometry-method issues rather than hiding method failures behind an invalid bevel. Whole dimensions are evaluated only after geometry is valid, with an explicit deferred notice otherwise. Error metadata identifies parts, structure and dimension stages; advancing to a later stage or reducing the current stage's failures counts as bounded recovery progress. The two-correction limit, atomic application and unchanged-failure circuit breaker remain intact. A wrong `assembly` plan must be explicitly revised under the same feature identity before rebuilding; the validator does not force extra fake parts or silently relax a profile/sweep/mesh declaration.

Blueprint `dimensionsSource` distinguishes explicit user dimensions (`user`, hard 2%/2mm tolerance) from image estimates (`estimated`, reported but not a hard absolute-size constraint). Old persisted plans without provenance retain the legacy hard constraint; newly proposed reference-image plans default missing provenance to estimated. Estimated discrepancies remain visible in build/repair receipts, and reference proportion checks remain separate. Thin-box bevel limits and the exact invalid lathe point/height are exposed in tool guidance. Error summaries no longer claim the latest failure is a bevel merely because an older bevel error exists in the transcript. Coverage is in `tests/structured-component.mjs` and `tests/reference-proportions.mjs`; these synthetic checks do not establish real model fidelity.
